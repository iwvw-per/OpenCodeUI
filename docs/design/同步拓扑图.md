## 一、物理部署拓扑

opencode 后端跑在**每一台主机**上，前端只是客户端。没有中央同步服务。

```
                    ┌──────────────────────────────────────────────┐
                    │            API Monitor 账号服务                │
                    │            {domain}                            │
                    │                                                │
                    │  /api/aiagent/auth/login     ← 登录换令牌       │
                    │  /api/aiagent/instances      ← 实例清单         │
                    │  /api/aiagent/gw/{instanceId} ← 网关转发到主机   │
                    │  /api/aiagent/preferences     ← 偏好读写        │
                    │  /api/aiagent/preferences/events ← 偏好变更SSE  │
                    └───────▲───────────────────────▲────────────────┘
                            │                       │
                 账号通道 (B/C 类)              网关转发 (A 类)
                            │                       │
        ┌───────────────────┴───────┐               │
        │                           │               │
   ┌────┴─────┐              ┌──────┴─────┐        │
   │ 设备 A    │              │ 设备 B      │        │
   │ (桌面/网页/│              │ (桌面/网页/ │        │
   │  安卓)    │              │  安卓)      │        │
   └────┬─────┘              └──────┬─────┘        │
        │                           │               │
        │ opencode SSE              │ opencode SSE  │
        │ + HTTP (A 类)             │ + HTTP (A 类) │
        └───────────┬───────────────┘               │
                    │                               │
        ┌───────────▼───────────┐                   │
        │  主机 1                │◀──────────────────┘
        │  opencode serve        │
        │  (后端权威数据源)       │
        └───────────────────────┘
                    ▲
                    │ 同一台或不同主机
        ┌───────────┴───────────┐
        │  主机 2                │
        │  opencode serve        │
        └───────────────────────┘
```

要点：

1. **A 类（会话状态/消息）没有中央服务**：设备直接连后端。两台设备连**同一个**后端才谈得上同步；各连各的主机时本就该不同。
2. **B/C 类（偏好/已读水位）走账号服务**：这是一条独立的跨端通道，与 opencode 后端无关。
3. 主机可以是本机（`local`），也可以是远端（`aiagent:inst_xxx` 经网关）。

## 三、数据流：按类别

### 3.1 A 类（服务端权威）— 每条 server 一条 SSE

```
opencode 后端
   │
   │  SSE /global/event  (双发: 原始事件 + sync(seq))
   ▼
events.ts  parseAndCoalesce → broadcastEvent
   │
   │  原始事件 (payload.type + properties)      ← 客户端消费
   │  sync 事件 (payload.type:"sync" + seq)     ← 客户端丢弃(缺口检测未实现)
   │                                             seq 为 per-aggregate, 不可重放
   ▼
useGlobalEvents.buildServerCallbacks(serverId)
   │  scope(sid) = serverId::sessionId
   ├─▶ messageStore           (message.updated / part.*)
   ├─▶ sessionListIndexStore  (session.created/updated/deleted)
   ├─▶ childSessionStore      (子会话关系/状态)
   ├─▶ activeSessionStore     (session.status/idle/error, permission/question)
   └─▶ notificationStore.push (由忙转闲且不在看 → completed)
   │
   ▼
Store → useSyncExternalStore → 组件重渲染

触发点（HTTP 快照，补 SSE 遗漏）:
  首次连接 / 重连 / 回前台 / 目录变化 / 打开会话
   │
   ├─ getSessionStatus(directory, serverId)  ← 按目录过滤(问题根因)
   ├─ getPendingPermissions / getPendingQuestions
   └─ getSessions / getSessionMessages ...
```

### 3.2 B 类（账号偏好）— 独立账号通道

```
设备 A 改偏好
   │  localStorage.setItem + serverStorage 版本通知
   ▼
preferencesSyncEngine  subscribePerServerStorageVersion
   │  500ms 防抖
   ▼
pushPreferences → POST /api/aiagent/preferences
   │
   ▼
账号服务存储
   │
   │  SSE /api/aiagent/preferences/events  (只推 key 名)
   ▼
设备 B  preferencesEvents.subscribePreferenceEvents
   │
   ▼
pullPreferences → GET /api/aiagent/preferences
   │  逐键时间戳 LWW + 聚合键三方合并 + 墓碑
   ▼
写 localStorage → notifyPerServerStorageChanged
   │
   ▼
layoutStore.reloadFromStorage() 等 → UI 重读
```

### 3.3 C 类（设备本地派生）

```
未读:      notificationStore (localStorage opencode:notifications)  ← 当前各端独立
已读:      本地点击 → markRead                                ← 当前各端独立
项目时间:   useProjectLastUsedAt → GET /session?directory=     ← 各端各自查,60s缓存
排序锚点:   sessionActivityStore (内存,派生自消息)
侧栏开合:   layoutStore (localStorage, 有意排除跨端同步)
```

**这三类当前都不跨端共享，是多端不一致的直接来源。设计拟改：**

```
未读/已读 → 改为「已读水位」{sessionId: 校准时间戳}, 走 B 类通道, max 合并
项目时间  → 改用 A 类的服务端 time.updated
侧栏开合  → 保持本地
```

## 四、多端一致性：哪些一致、哪些不一致

| 数据 | 通道 | 多端是否一致 | 原因 |
|---|---|---|---|
| 消息正文 | A / SSE | ✅ 一致（同后端） | 都从后端派生 |
| busy/retry | A / SSE | ✅ 理论一致 | 都从后端派生，但受目录切分 bug 影响 |
| 会话列表 | A / SSE | ✅ 一致（同后端） | sessionListIndexStore |
| 权限/提问 | A / SSE | ✅ 一致 | activeSessionStore |
| 主题/模型/置顶 | B / 账号 | ✅ 一致（需登录） | preferencesSync |
| **未读/已读** | C / 本地 | ❌ **不一致** | 各端独立算（待改为水位同步） |
| **项目时间戳** | C / 本地 | ❌ **不一致** | 各端各自查（待改用服务端时间） |
| 列表排序 | C / 本地锚点 | ⚠️ 近似 | 锚点本地派生 |
| 侧栏开合 | C / 本地 | 有意不一致 | 属浏览状态 |

## 五、延迟来源标注

```
设备 A ──[1]──▶ 后端 ──[2]──▶ 设备 B        (A 类)
设备 A ──[3]──▶ 账号服务 ──[4]──▶ 设备 B     (B/C 类)

[1][2] = 各设备到后端的网络延迟
        本机直连: 毫秒级
        网关隧道: ~1.1s 固定往返 (代码注释实测)
        → 桌面直连 + 网页隧道时, 两端天然相差 >1s

[3][4] = 账号通道延迟
        写: 500ms 防抖 + POST
        推: SSE key 名
        拉: GET 取值
        → 几百毫秒到数秒
```

关键：**延迟只造成滞后，不造成错误**（收敛型合并保证）：

| 合并 | 语义 | 延迟下行为 |
|---|---|---|
| 会话状态 | replace-scope + seq 缺口检测（快照重拉修复） | 滞后后收敛 |
| 已读水位 | max 单调递增 | 多显示一会儿未读，永不回退 |
| 偏好 | 三方合并 + 时间戳 | 收敛 |

## 六、连接方式：Tauri vs Browser

| 维度 | 桌面/安卓 (Tauri) | 网页 (Browser) |
|---|---|---|
| opencode SSE | Rust `bridge_connect`（reqwest + Channel） | `fetch` + ReadableStream |
| 账号 SSE | `getUnifiedFetch()` (plugin-http) | `fetch` |
| HTTP | plugin-http | fetch |
| 后台行为 | Android 有前台服务/实况通知，WebView 冻结 | 浏览器标签页节流 |
| 认证 | bridge 传 authHeader；账号走 Bearer | 同 |

两条路径在 `events.ts` 汇合到同一个 `broadcastEvent`，上层无差异。

## 七、拓扑暴露的三个结构性问题

1. **A 类无中央服务** → 跨端一致性只能靠「每端都正确」，不能靠服务端仲裁。所以 §11 强调「滞后但收敛」，而非强一致。
2. **B/C 类跨端依赖账号** → 未登录设备无法跨端共享偏好与已读。纯本地直连场景无跨端能力。
3. **多前缀指向同一后端** → `local` 与 `aiagent:inst_x` 可能是同一实例。`messageStore.rawSessionToKey` 只做单端内存归并；跨端水位/状态需要**稳定的后端实例身份**才能对齐（设计待决 #7）。

## 八、一图总结：三类数据、两条通道、一个收敛目标

```
                    ┌─────────────────────────────┐
                    │      收敛目标（延迟可容忍）    │
                    │  最终一致, 永不回退, 滞后收敛  │
                    └──────────────▲──────────────┘
                                   │
          ┌────────────────────────┼────────────────────────┐
          │                        │                        │
     A 类: 服务端权威          B 类: 账号偏好           C 类: 本地派生
          │                        │                        │
   opencode SSE+HTTP        账号 SSE+HTTP          当前各端独立
   (每 server 一条)         (全局一条)             拟: 水位/服务端时间
          │                        │                        │
   replace-scope            三方合并+LWW+墓碑          max 水位
   + seq 缺口检测
          │                        │                        │
          └────────────┬───────────┴────────────┬───────────┘
                       │                        │
              无中央服务, 每端连后端      有账号服务, 跨端通道
              (同后端才一致)            (需登录)
```
