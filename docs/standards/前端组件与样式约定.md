# 前端组件与样式约定

最后更新：2026-09-17

本文件约束 `src/` 下的 UI 实现方式，目的是消除同一控件在不同模块各写一遍导致的样式与行为漂移。

## 一、基础组件优先

`src/components/ui/` 是唯一的基础组件来源。写界面时先查这里是否已有可用组件，不要直接手写原生元素。

现有组件：

| 分类 | 组件 |
|---|---|
| 动作 | `Button` `IconButton` `CopyButton` `MenuItem` `ContextMenuItem` |
| 表单 | `Input` `Textarea` `Label` `Checkbox` `Switch` `Select` 系列 |
| 导航 | `Tabs` `TabsList` `TabsTrigger` `TabsContent` `ScrollArea` |
| 浮层 | `Dialog` `DropdownMenu` `Popover` `Tooltip` `ModalShell` |

`Tabs` 有三种视觉变体，按场景选用：

| 变体 | 场景 |
|---|---|
| `segmented`（默认） | 视图切换（如侧边栏主机/项目） |
| `slider` | 设置项等需要滑块位移动画的分段选择 |
| `underline` | 内容区顶部的下划线式导航 |

### 导入方式

```ts
// 推荐：从统一出口导入
import { Button, Input, Tabs, TabsList, TabsTrigger } from '../components/ui'

// 避免：直接引具体文件路径（会绕过 barrel，重构时找不到调用方）
import { Button } from '../components/ui/Button'
```

## 二、样式写法

### 颜色只用设计令牌

```tsx
// 正确
<div className="bg-bg-100 text-text-200 border-border-200" />
<span className="text-accent-main-100" />

// 禁止
<div className="bg-white text-black" />
<div style={{ color: '#fff' }} />
```

可用令牌见 `src/index.css` 的 `@theme` 块。7 套主题 × 明暗模式都会覆盖这些变量，硬编码颜色无法跟随主题切换。

### 强调色的正确用法

激活/选中态用**浅底 + 主文字色**，不要用高饱和实色铺满：

```tsx
// 正确：全主题下对比度 >= 9.9:1
'bg-accent-main-100/15 text-text-100'

// 禁止：白字对 accent 底对比度最低仅 2.1:1，且视觉过重
'bg-accent-main-100 text-white'
```

需要实色强调背景时，文字必须用 `text-oncolor-100`（主题感知的对比色），而不是硬编码 `text-white`。

### 用 cn 合并类名

组件接受 `className` 时，用 `cn()` 合并，让调用方传入的类能正确覆盖默认值：

```tsx
import { cn } from '../../utils/cn'

className={cn('px-2.5 text-[length:var(--fs-sm)]', sizeStyles[size], className)}
```

`cn` 内部用 tailwind-merge 消解同类冲突（`px-5` 会覆盖 `px-2.5`），手写字符串拼接做不到这点。

## 三、组件编写约定

### 结构

```tsx
import { forwardRef } from 'react'
import { cn } from '../../utils/cn'

export interface FooProps extends React.HTMLAttributes<HTMLDivElement> {
  variant?: 'a' | 'b'
}

export const Foo = forwardRef<HTMLDivElement, FooProps>(({ className, variant = 'a', ...props }, ref) => (
  <div ref={ref} className={cn(baseStyles, variantStyles[variant], className)} {...props} />
))
Foo.displayName = 'Foo'
```

要点：

- `forwardRef` 转发 ref，让调用方能拿到 DOM 节点（聚焦、定位、测量都需要）。
- 变体样式抽成 `Record<Variant, string>` 常量，不要写成嵌套三元表达式。
- 必须设 `displayName`，否则 React DevTools 里显示为匿名组件。
- 透传 `...props`，不要吞掉调用方的原生属性。

### 复杂交互用 Radix 原语

涉及键盘导航、焦点管理、ARIA、碰撞避让的组件（Tabs / Select / Popover / Tooltip / Checkbox / Switch / Dialog），基于 `@radix-ui/react-*` 实现。Radix 只提供行为与无障碍支持，不带任何样式，视觉仍由本项目的设计令牌控制。

不要自己手写这些逻辑 —— 焦点陷阱、roving tabindex、ESC 关闭这些细节极易出错。

### 什么时候该抽组件

同一控件在**两处以上**出现，或单个文件里同种原生元素超过 5 个时，应当抽成基础组件。判断标准不是"能不能抽"，而是"下次别人写这个控件时会不会又写一遍"。

## 四、测试约定

基础组件测试放在 `src/components/ui/` 下，与组件同目录。

- 用 `@testing-library/react` 的 `fireEvent`（项目未引入 `user-event`）。
- 断言语义与结构（role、aria 属性、data-state），不断言具体类名 —— 除非是回归保护（如防止激活态退回 `text-white`）。
- 不测第三方原语的行为（Radix 自身保证），只测自己写的样式映射与结构契约。

注意两个 Radix 在 jsdom 下的行为：

- `TabsTrigger` 在 `mouseDown` 上激活，不是在 `click` 上。测试需 `fireEvent.mouseDown` 并包在 `act` 里。
- 非激活的 `TabsContent` 节点仍在 DOM，但不带 `role="tabpanel"` 且内容为空。

## 五、待办：渐进式收敛

现有代码中存在大量手写控件（约 383 处裸 `<button>`、89 处裸 `<input>`）。迁移策略是**渐进**的：

1. 新代码一律使用基础组件。
2. 修改老文件时，顺手把该文件内的手写控件换成基础组件。
3. 不做专门的大规模替换 —— 那类改动风险高且难以验证。

已完成的高价值迁移：

- `SidePanel.tsx` 的主机/项目切换 → `Tabs`（原先手写，激活态对比度不达标）。
- `SettingsUI.tsx` 的 `Toggle` → 内部改用 `Switch`（原先手写按钮 + 硬编码 `bg-white` 滑块，深色主题下不跟随令牌）。
- `SettingsUI.tsx` 的 `SegmentedControl` → 内部改用 `Tabs` 的 slider 变体（原先手写键盘处理，且缺 ARIA 关联）。
- `PanelContainer.tsx` 的面板右键/新增菜单 7 处行按钮 → `ContextMenuItem`。
- `FileExplorer.tsx` 的清空搜索、刷新按钮 → `IconButton`；右键菜单项 → `ContextMenuItem`。
